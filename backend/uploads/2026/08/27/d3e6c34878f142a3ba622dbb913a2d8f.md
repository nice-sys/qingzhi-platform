# 数据库系统概论 · 第八章 数据库编程

# 第八章 数据库编程

前面我们学习了标准SQL语言，它是一种声明式语言，只需要说明"做什么"，不需要说明"怎么做"。但在实际应用开发中，很多复杂的业务逻辑仅用标准SQL难以实现，需要结合过程化编程。本章介绍数据库编程的两种主要方式：在数据库端运行的过程化SQL（存储过程、函数），以及在应用端通过高级语言（Java）使用JDBC访问数据库。

## 8\.1 概述

SQL是访问关系数据库的标准语言，功能强大，但它有自身的局限性。为了满足复杂应用的需求，数据库系统提供了多种扩展方式。

### 8\.1\.1 SQL表达能力的限制

标准SQL是声明式的非过程化语言，它的表达能力有以下局限：

1. **缺少流程控制**：SQL没有分支（if\-else）、循环（for/while）等过程化控制结构，无法实现复杂的业务逻辑；

2. **不能逐行处理**：SQL是面向集合的，一次操作一个元组集合，但有些业务需要逐行处理查询结果；

3. **复杂计算困难**：SQL不适合做复杂的数值计算、字符串处理、业务规则判断；

4. **无法交互**：SQL本身不能和用户交互，不能弹出对话框、接收用户输入；

5. **不能访问外部系统**：SQL无法直接访问文件、网络、其他系统接口。

例如，要实现"根据学生的平均成绩给出等级（90分以上优秀，80\-89良好，70\-79中等，60\-69及格，60以下不及格）"这样的逻辑，仅用标准SQL写起来很麻烦，而且不通用。

### 8\.1\.2 扩展SQL的功能

为了弥补SQL的不足，各数据库厂商在标准SQL基础上扩展了过程化功能：

- **过程化SQL**：在SQL中加入变量、分支、循环、游标等过程化元素，形成完整的编程语言，如Oracle的PL/SQL、SQL Server的T\-SQL、PostgreSQL的PL/pgSQL、MySQL的存储过程语言；

- **存储过程和函数**：把过程化SQL编译后保存在数据库服务器端，应用程序可以直接调用，减少网络传输；

- **触发器**：在第五章已经学过，是特殊的存储过程，在特定事件发生时自动执行；

- **嵌入式SQL**：把SQL语句嵌入到C、Java等高级语言中，由预编译器处理；

- **调用层接口**：通过标准API在高级语言中访问数据库，如ODBC、JDBC。

### 8\.1\.3 通过高级语言实现复杂应用

数据库只是存储和管理数据，完整的应用系统还需要界面、业务逻辑、网络通信等，这些都要用高级语言（Java、Python、C\#等）实现。高级语言访问数据库主要有两种方式：

1. **嵌入式SQL**：把SQL语句直接写在高级语言代码中，编译前用预编译器把SQL转换成函数调用。这种方式现在用得比较少；

2. **调用层接口（CLI）**：通过标准的API函数来访问数据库，SQL语句以字符串形式传递给数据库。最典型的就是ODBC（开放数据库连接）和JDBC（Java数据库连接）。

这两种方式各有优势：存储过程在数据库端运行，速度快，减少网络流量，但和具体数据库绑定；JDBC/ODBC在应用端运行，灵活，跨数据库，但网络开销大。实际开发中通常两者结合使用。

**两种编程方式对比：**过程化SQL（存储过程）是"在数据库里写程序"，数据不用出数据库，效率高；JDBC是"在程序里访问数据库"，灵活，能做复杂的界面和业务逻辑。两者不是互斥的，复杂应用通常会同时使用。

## 8\.2 过程化SQL

过程化SQL（Procedural SQL）是在标准SQL基础上增加了过程化编程元素的语言，不同数据库有不同实现：Oracle是PL/SQL，SQL Server是T\-SQL，PostgreSQL是PL/pgSQL，MySQL也支持存储过程。虽然语法有差异，但核心概念是一样的。

### 8\.2\.1 过程化SQL的块结构

过程化SQL的基本单位是**块（Block）**，所有程序都由块组成。块分为三部分：

```
[DECLARE
    -- 声明部分：定义变量、常量、游标、异常等]
BEGIN
    -- 执行部分：SQL语句和过程化语句，这部分是必须的
[EXCEPTION
    -- 异常处理部分：处理运行时错误]
END;
```

说明：

- 声明部分和异常处理部分是可选的，执行部分必须有；

- 块可以嵌套，一个块的执行部分里可以包含另一个子块；

- 块可以是匿名的（直接执行），也可以命名（就是存储过程或函数）。

一个简单的匿名块例子（MySQL语法）：

```
BEGIN
    DECLARE v_count INT;
    SELECT COUNT(*) INTO v_count FROM Student;
    SELECT v_count AS 学生总数;
END;
```

### 8\.2\.2 变量和常量的定义

在DECLARE部分可以定义变量和常量。

#### 一、变量定义

语法：`变量名 数据类型 [DEFAULT 默认值];`

常用数据类型和SQL一样：INT、VARCHAR、DATE、NUMBER等。

例子：

```
DECLARE
    v_sno CHAR(9);
    v_sname VARCHAR(20);
    v_age INT DEFAULT 20;
    v_avg_grade NUMBER(5,2);
```

变量赋值有两种方式：

1. 用SET语句：`SET v_age = 21;`

2. 用SELECT \.\.\. INTO：把查询结果赋值给变量：

    ```
    SELECT Sname, Sage INTO v_sname, v_age
    FROM Student WHERE Sno = '202200001';
    ```

#### 二、常量定义

用CONSTANT关键字定义常量，必须赋值，不能修改：

```
DECLARE
    c_pass_score INT CONSTANT DEFAULT 60;
    c_school VARCHAR(20) CONSTANT DEFAULT '北航';
```

#### 三、%TYPE和%ROWTYPE

为了让变量类型和表列类型自动匹配，可以用%TYPE：

```
DECLARE
    v_sname Student.Sname%TYPE;  -- 类型和Student.Sname列一样
    v_sno Student.Sno%TYPE;
```

如果要表示一整行，可以用%ROWTYPE：

```
DECLARE
    v_student Student%ROWTYPE;  -- 包含Student表的所有列
BEGIN
    SELECT * INTO v_student FROM Student WHERE Sno = '202200001';
    -- 用 变量名.列名 访问
    SELECT v_student.Sname, v_student.Sage;
END;
```

### 8\.2\.3 流程控制

过程化SQL支持分支和循环结构，这是它比标准SQL强大的地方。

#### 一、分支结构（IF）

语法：

```
IF 条件1 THEN
    语句1;
[ELSIF 条件2 THEN
    语句2;]
[ELSE
    语句3;]
END IF;
```

例子：根据分数判断等级

```
IF v_grade >= 90 THEN
    SET v_level = '优秀';
ELSIF v_grade >= 80 THEN
    SET v_level = '良好';
ELSIF v_grade >= 70 THEN
    SET v_level = '中等';
ELSIF v_grade >= 60 THEN
    SET v_level = '及格';
ELSE
    SET v_level = '不及格';
END IF;
```

还有CASE语句，和SQL中的CASE表达式类似，但可以作为语句使用：

```
CASE v_dept
    WHEN 'CS' THEN SET v_dept_name = '计算机系';
    WHEN 'IS' THEN SET v_dept_name = '信息系';
    WHEN 'MA' THEN SET v_dept_name = '数学系';
    ELSE SET v_dept_name = '其他系';
END CASE;
```

#### 二、循环结构

有三种基本循环：

**1\. LOOP循环（最简单）**

```
LOOP
    语句;
    IF 退出条件 THEN
        LEAVE;  -- 退出循环
    END IF;
END LOOP;
```

**2\. WHILE循环（先判断后执行）**

```
WHILE 条件 DO
    语句;
END WHILE;
```

**3\. FOR循环（遍历游标或数字范围）**

```
FOR i IN 1..10 LOOP
    DBMS_OUTPUT.PUT_LINE(i);  -- 输出1到10
END LOOP;
```

例子：计算1到100的和

```
DECLARE
    v_sum INT DEFAULT 0;
    v_i INT DEFAULT 1;
BEGIN
    WHILE v_i <= 100 DO
        SET v_sum = v_sum + v_i;
        SET v_i = v_i + 1;
    END WHILE;
    SELECT v_sum AS 总和;
END;
```

### 8\.2\.4 游标的定义与使用

SQL是面向集合的，一个SELECT语句返回多行元组。但过程化程序有时候需要**逐行处理**结果集，这时候就需要游标（Cursor）。游标是一个指向结果集的指针，可以逐行向前移动，取出每一行的数据处理。

#### 一、游标的使用步骤

1. **声明游标**：定义游标对应的SELECT语句；

2. **打开游标**：执行查询，结果集准备好，游标指向第一行之前；

3. **取数据**：把游标指向的当前行数据取出，游标向前移动一行；

4. **关闭游标**：处理完后关闭，释放资源。

#### 二、语法

声明游标：

```
DECLARE 游标名 CURSOR FOR SELECT语句;
```

打开游标：`OPEN 游标名;`

取一行数据：`FETCH 游标名 INTO 变量1, 变量2, ...;`

关闭游标：`CLOSE 游标名;`

#### 三、例子：逐行打印所有学生姓名

```
DECLARE
    v_sname Student.Sname%TYPE;
    -- 声明游标
    DECLARE cur_student CURSOR FOR
        SELECT Sname FROM Student;
BEGIN
    -- 打开游标
    OPEN cur_student;
    -- 循环取数
    read_loop: LOOP
        FETCH cur_student INTO v_sname;
        -- 处理完退出
        IF done THEN LEAVE read_loop; END IF;
        SELECT v_sname;  -- 处理这一行
    END LOOP;
    -- 关闭游标
    CLOSE cur_student;
END;
```

#### 四、游标的优缺点

- 优点：可以逐行处理，实现复杂的业务逻辑；

- 缺点：速度慢，开销大，因为要在数据库服务器上维护游标状态；

- 原则：能用集合操作（普通SQL）就不用游标，只有确实需要逐行处理时才用。

**注意：**不同数据库的过程化SQL语法差异较大，以上是通用概念和MySQL风格语法。考试时以教材上的语法为准，重点掌握块结构、变量、IF/LOOP、游标的概念和使用步骤。

### 8\.2\.5 存储过程

前面的匿名块只能执行一次，不能保存，也不能被其他程序调用。**存储过程（Stored Procedure）**就是命名的、编译后保存在数据库中的过程化SQL块，可以被反复调用。

#### 一、创建存储过程

语法（MySQL）：

```
CREATE PROCEDURE 过程名([参数列表])
[特性]
BEGIN
    过程体（过程化SQL语句）
END;
```

参数有三种模式：

- **IN**：输入参数，调用者传值给过程（默认）；

- **OUT**：输出参数，过程把结果返回给调用者；

- **INOUT**：既是输入又是输出。

例子1：创建存储过程，查询某个学生的平均成绩

```
CREATE PROCEDURE GetStudentAvg(
    IN p_sno CHAR(9),      -- 输入：学号
    OUT p_avg NUMBER(5,2)  -- 输出：平均成绩
)
BEGIN
    SELECT AVG(Grade) INTO p_avg
    FROM SC
    WHERE Sno = p_sno;
END;
```

例子2：创建存储过程，根据学号删除学生（同时删除选课记录）

```
CREATE PROCEDURE DeleteStudent(IN p_sno CHAR(9))
BEGIN
    DELETE FROM SC WHERE Sno = p_sno;
    DELETE FROM Student WHERE Sno = p_sno;
END;
```

#### 二、调用存储过程

用CALL语句调用：

```
-- 调用GetStudentAvg，用变量接收结果
CALL GetStudentAvg('202200001', @v_avg);
SELECT @v_avg AS 平均成绩;

-- 调用DeleteStudent
CALL DeleteStudent('202200001');
```

#### 三、删除存储过程

```
DROP PROCEDURE IF EXISTS GetStudentAvg;
```

#### 四、存储过程的优点

1. **运行速度快**：存储过程编译后保存在数据库中，第一次执行后就缓存了，不用每次编译；

2. **减少网络流量**：只需要传过程名和参数，不用传长长的SQL语句；

3. **复用性好**：一次编写，反复调用，多个应用可以共用；

4. **安全性高**：可以只给用户调用存储过程的权限，不给直接访问表的权限；

5. **封装业务逻辑**：把复杂的业务逻辑放在数据库端，保证逻辑一致。

#### 五、存储过程的缺点

- **可移植性差**：不同数据库的存储过程语法不一样，迁移数据库要重写；

- **调试困难**：数据库端调试工具不如高级语言方便；

- **占用数据库服务器资源**：复杂的存储过程会增加数据库服务器负担；

- **版本管理困难**：存储过程存在数据库里，不如代码文件好做版本控制。

### 8\.2\.6 存储函数

**存储函数（Stored Function）**和存储过程很像，也是命名的、保存在数据库中的过程化SQL块，但它必须返回一个值，通常用在SQL语句内部，就像内置函数（COUNT、AVG）一样。

#### 一、创建存储函数

语法：

```
CREATE FUNCTION 函数名([参数列表])
RETURNS 返回类型
[特性]
BEGIN
    函数体;
    RETURN 返回值;
END;
```

注意：存储函数的参数都是IN模式，没有OUT或INOUT，因为它本身就是返回一个值。

例子：创建函数，根据学号返回学生的平均成绩

```
CREATE FUNCTION GetAvgGrade(p_sno CHAR(9))
RETURNS NUMBER(5,2)
DETERMINISTIC
BEGIN
    DECLARE v_avg NUMBER(5,2);
    SELECT AVG(Grade) INTO v_avg
    FROM SC WHERE Sno = p_sno;
    RETURN v_avg;
END;
```

#### 二、调用存储函数

存储函数可以像内置函数一样用在SQL语句中：

```
-- 查询每个学生的姓名和平均成绩
SELECT Sname, GetAvgGrade(Sno) AS 平均成绩
FROM Student;

-- 或者直接调用
SELECT GetAvgGrade('202200001');
```

#### 三、存储过程和存储函数的区别

|对比项|存储过程|存储函数|
|---|---|---|
|返回值|可以有0个或多个（通过OUT参数）|必须有且只有一个返回值|
|调用方式|用CALL语句单独调用|用在SQL语句中，和内置函数一样|
|参数模式|支持IN、OUT、INOUT|只支持IN|
|用途|完成一系列操作（增删改查、事务）|计算并返回一个值|
|SQL中使用|不能用在SELECT等语句中|可以出现在SELECT、WHERE等子句中|

#### 四、删除存储函数

```
DROP FUNCTION IF EXISTS GetAvgGrade;
```

**什么时候用存储过程/函数？**当业务逻辑复杂、多个地方重复使用、对性能要求高、需要减少网络流量时，可以考虑用存储过程。但现在互联网应用更倾向于把业务逻辑放在应用层，存储过程用得越来越少，主要在传统企业应用和数据仓库中使用。

## 8\.3 JDBC编程

JDBC（Java Database Connectivity）是Java语言访问关系数据库的标准API。它定义了一组统一的接口，让Java程序可以用相同的方式访问不同的数据库，不用为每个数据库写不同的代码。

### 8\.3\.1 JDBC工作原理概述

JDBC的核心思想是"面向接口编程"：SUN公司定义了一组标准接口（java\.sql包下的Connection、Statement、ResultSet等），各数据库厂商提供这些接口的实现，叫做**JDBC驱动（Driver）**。

工作原理：

1. Java程序只调用JDBC标准接口的方法，不直接调用数据库厂商的API；

2. JDBC驱动管理器把调用转给对应数据库的驱动；

3. 驱动把JDBC调用转换成数据库能理解的网络协议，发给数据库服务器；

4. 数据库执行SQL，返回结果；

5. 驱动把结果转换成JDBC标准格式，返回给Java程序。

好处：

- **跨数据库**：换数据库只需要换驱动和连接字符串，Java代码几乎不用改；

- **跨平台**：JDBC是Java标准，所有支持Java的平台都能用；

- **简单**：不用学习每个数据库的专有API，学会JDBC就能访问所有数据库。

### 8\.3\.2 JDBC APIs基础

JDBC核心类和接口都在java\.sql包中，最常用的有：

#### 一、DriverManager

驱动管理器，负责加载驱动、建立数据库连接。

- `getConnection(url, user, password)`：建立数据库连接，返回Connection对象；

- URL格式：`jdbc:子协议://主机:端口/数据库名`，例如MySQL是`jdbc:mysql://localhost:3306/studentdb`。

#### 二、Connection

代表和数据库的一次连接，所有数据库操作都在连接基础上进行。常用方法：

- `createStatement()`：创建Statement对象，用来执行SQL；

- `prepareStatement(sql)`：创建PreparedStatement对象，执行参数化SQL（推荐）；

- `setAutoCommit(false)`：关闭自动提交，开启事务；

- `commit()`：提交事务；

- `rollback()`：回滚事务；

- `close()`：关闭连接。

#### 三、Statement和PreparedStatement

用来执行SQL语句。Statement是直接执行静态SQL，PreparedStatement是预编译的参数化SQL（更安全、更快）。

常用方法：

- `executeQuery(sql)`：执行SELECT查询，返回ResultSet；

- `executeUpdate(sql)`：执行INSERT/UPDATE/DELETE，返回影响的行数；

- `execute(sql)`：执行任意SQL，返回boolean表示是否有结果集。

PreparedStatement可以用?作为参数占位符，然后用setXxx方法设置参数：

```
PreparedStatement pstmt = conn.prepareStatement(
    "SELECT * FROM Student WHERE Sdept = ? AND Sage > ?");
pstmt.setString(1, "CS");  // 第一个?，下标从1开始
pstmt.setInt(2, 20);       // 第二个?
ResultSet rs = pstmt.executeQuery();
```

#### 四、ResultSet

结果集，代表查询返回的元组集合，类似游标，可以逐行遍历。

- `next()`：移动到下一行，返回true表示还有数据；

- `getXxx(列名或列序号)`：取出当前行某列的值，如getString、getInt、getDate；

- 列序号从1开始，不是从0开始。

遍历例子：

```
while (rs.next()) {
    String sno = rs.getString("Sno");
    String sname = rs.getString("Sname");
    int sage = rs.getInt("Sage");
    System.out.println(sno + " " + sname + " " + sage);
}
```

### 8\.3\.3 使用JDBC操纵数据库的工作流程

使用JDBC访问数据库有固定的7步流程，记住这个流程就会写JDBC代码了。

#### 第一步：加载驱动

旧版本JDBC需要手动加载驱动类：

```
Class.forName("com.mysql.cj.jdbc.Driver");
```

新版本JDBC（4\.0\+）会自动加载驱动，只要把驱动jar包放在classpath中就行，这步可以省略。

#### 第二步：建立连接

用DriverManager\.getConnection\(\)建立和数据库的连接：

```
String url = "jdbc:mysql://localhost:3306/studentdb?useSSL=false";
String user = "root";
String password = "123456";
Connection conn = DriverManager.getConnection(url, user, password);
```

#### 第三步：创建Statement/PreparedStatement

推荐使用PreparedStatement，防止SQL注入，而且性能更好：

```
String sql = "INSERT INTO Student(Sno, Sname, Ssex, Sage, Sdept) VALUES (?,?,?,?,?)";
PreparedStatement pstmt = conn.prepareStatement(sql);
```

#### 第四步：设置参数（如果是PreparedStatement）

```
pstmt.setString(1, "202200100");
pstmt.setString(2, "张三");
pstmt.setString(3, "男");
pstmt.setInt(4, 20);
pstmt.setString(5, "CS");
```

#### 第五步：执行SQL

查询用executeQuery\(\)，增删改用executeUpdate\(\)：

```
// 增删改
int rows = pstmt.executeUpdate();
System.out.println("影响了" + rows + "行");

// 查询
ResultSet rs = pstmt.executeQuery();
```

#### 第六步：处理结果

如果是查询，遍历ResultSet：

```
while (rs.next()) {
    String sname = rs.getString("Sname");
    int sage = rs.getInt("Sage");
    System.out.println(sname + " " + sage);
}
```

#### 第七步：关闭资源

ResultSet、Statement、Connection都要关闭，顺序是先开后关。推荐用try\-with\-resources自动关闭：

```
// Java 7+ 自动关闭资源
```

#### JDBC事务处理

默认情况下，JDBC每条SQL自动提交。如果要手动控制事务：

```
try {
    conn.setAutoCommit(false);  // 关闭自动提交
    // 执行多条SQL
    pstmt1.executeUpdate();
    pstmt2.executeUpdate();
    conn.commit();  // 都成功才提交
} catch (SQLException e) {
    conn.rollback();  // 出错回滚
    e.printStackTrace();
} finally {
    conn.setAutoCommit(true);  // 恢复自动提交
}
```

**SQL注入问题：**用Statement拼接SQL字符串会有SQL注入风险，比如用户输入"' OR '1'='1"就能绕过密码验证。一定要用PreparedStatement，用?占位符传参数，不要拼接字符串！

## 本章小结

本章介绍了数据库编程的两种主要方式：数据库端的过程化SQL和应用端的JDBC编程。

1. **SQL的局限与扩展**：标准SQL是声明式语言，缺少流程控制，不能逐行处理，因此扩展出了过程化SQL，也可以通过高级语言\+JDBC实现复杂应用。

2. **过程化SQL块结构**：由声明部分、执行部分、异常处理部分组成，支持变量、常量、分支（IF/CASE）、循环（LOOP/WHILE/FOR）。

3. **游标**：用来逐行处理SELECT返回的结果集，使用步骤：声明→打开→取数→关闭。游标功能灵活但性能较低，尽量用集合操作。

4. **存储过程和函数**：命名的、编译后保存在数据库中的过程化SQL块。存储过程用CALL调用，可以有多个OUT参数；存储函数必须返回一个值，可以像内置函数一样用在SQL语句中。

5. **JDBC工作原理**：Java通过JDBC标准API\+数据库驱动访问数据库，实现了跨数据库编程。核心类：DriverManager、Connection、Statement/PreparedStatement、ResultSet。

6. **JDBC使用流程**：加载驱动→建立连接→创建Statement→设置参数→执行SQL→处理结果→关闭资源。推荐使用PreparedStatement防止SQL注入，用try\-with\-resources自动关闭资源。

|对比项|存储过程|JDBC应用程序|
|---|---|---|
|运行位置|数据库服务器端|应用服务器/客户端|
|语言|各数据库私有过程化SQL|标准Java\+JDBC API|
|性能|快，预编译，网络流量小|相对慢，网络流量大|
|可移植性|差，和数据库绑定|好，换数据库几乎不用改代码|
|灵活性|差，只能做数据库相关操作|好，能做界面、网络、文件等所有事|
|适用场景|复杂数据处理、批量操作|业务逻辑、用户界面、Web应用|
